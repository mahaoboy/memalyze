Most agent memory is a vector table. Fine, until someone asks.

Which customer data did the agent read last Tuesday? Can you show it without exporting the whole database? Can you deploy this inside a network with no outbound access? Those are the questions memalyze is built around.

Before write

Redact, then index

Phone numbers, e-mail, national IDs, bank cards, API keys and PEM blocks are replaced with stable markers before dedup, FTS and embedding. The plaintext is never stored — not by us, not by you.

Every read

Audit with hashes

Add, search and delete are appended to an audit table. The query is stored as SHA-256 + length, never plaintext. Export one CSV and hand it to an auditor.

Offline

One binary, local vectors

SQLite + Ollama. No model download at runtime, no cloud call. If Ollama is down, search degrades to keyword in ≤3 s and says degraded=true instead of hanging.

What it is not.

Written down here, not implied away in a SECURITY.md nobody reads.

  • No per-user auth. One token per process = one trust boundary. If two people must not read each other's memories, run two processes.
  • Pattern-based redaction. Eight families plus your own rules. It will not catch a name, an address, or a photo of an ID card. It is not a compliance certificate.
  • SQLite, single writer. Brute-force vector scan is fine up to roughly 10k memories. There is a store interface, but only SQLite is implemented.
  • Append-only at the SQL level, not WORM. A trigger rejects UPDATE; DELETE is not blocked. Export to object-lock or syslog storage if a hostile DBA is in your threat model.
  • AGPL-3.0. A commercial license is available for teams that cannot use it.
